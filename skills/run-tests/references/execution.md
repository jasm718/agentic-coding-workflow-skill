# 本地与 Jenkins 执行

本文件仅用于执行已确认的范围和环境。先读取项目规范和现有命令，工具可用时优先使用用途明确的接口；不假设通用脚本名、Jenkins 任务名或某个固定 IP 已存在。

## 本地

1. 核对工作目录、代码状态和实际被测版本，检查必要的依赖、模型字段、程序路径、账号配置及专用数据是否已具备。只读取必要信息，不打印秘密。
2. 使用项目已有选例入口，核对 ID 清单和预览结果。新运行使用独立产物目录或项目约定的清理方式，不混入历史报告。
3. 在确认的目录运行确认的命令。浏览器/客户端及真实数据操作从此阶段才开始；需要安装或重新部署才能加载新代码时必须已经包含在确认方案中。
4. 跟踪进程、退出码及报告。遵循项目的资源隔离、取消和清理机制，不为通过而改变测试断言或跳过失败。
5. 对照确认清单核对实际结果，打开生成的总览及必要操作报告定位失败。不重新构建或换环境来替代尚未完成的本次验证。

初始依赖或环境不完整时说明缺失项。若补齐需要尚未授权的安装部署，先提出具体动作；不要只因为存在本地源码就假定已经部署当前版本。

## Jenkins

1. 确认连接的实例、任务类型、分支/提交、参数、执行节点和队列状态；凭据用项目已有来源。读取 Jenkinsfile 与实际任务配置，理解是否先构建、是否部署、是否附带其他测试或自动发布。
2. 选择对应的成功 CI 构建及产物，核对其版本、测试代码和用例清单。测试须与被测产物的提交匹配；本地未提交变化、分支最新 HEAD 或本地 dev 清单不会自动进入旧构建。
3. 使用任务真实支持的参数触发一次。既有 CD 只接受上游构建号时，不编造任意 ID 参数或重新取最新测试代码绕过同提交约束。
4. 记录队列项，关联实际构建号和 URL。触发响应超时或不确定时，先查队列/最近构建确认是否已创建，避免重复部署和运行。
5. 跟踪到成功、失败、取消或明确阻塞，按合理间隔获取状态并汇报变化。出现等待输入或离线节点时说明原因与下一步；不把“已排队”当成测试完成。
6. 读取控制台、测试摘要和操作报告，核对实际选中的用例、版本和环境。流水线在构建或部署阶段失败则 E2E 为未执行；成功状态不能替代用例结果核验。

用户确认已明确列出的 Jenkins 流程，包含其中已说明的构建/部署/测试，无需每个阶段再次确认。但流程会自动发布且用户只批准测试时，必须在触发前解决授权和任务选择，不能先触发再解释。

不要修改 Jenkins 全局安全配置、重命名任务、调节点或创建新流水线来完成一个运行请求。现有机制无法执行确认范围时说明缺口，不静默改跑全部用例或换另一套环境。

## 失败与结果

- 产品断言失败：列出具体用例、步骤、预期和实际结果及证据，不自动修改产品代码。
- 脚本/收集错误：标明测试未正确执行；不能靠删用例或吞错误产生通过。
- 模型/网络/设备问题：与业务结果区分，说明哪些用例失败或未执行；不盲目归因产品 Bug。
- 构建/部署失败：报告失败阶段，未启动的 E2E 明确未执行。

遵循确认方案和项目既定重试策略，不无限重跑；重跑需要额外授权时先说明具体范围，原始失败记录必须保留。变更版本、范围或环境需要重新确认，不能覆盖原记录制造通过。

最终结果至少关联：版本/提交、执行环境、本地报告或 Jenkins 构建链接、确认 ID 与实际 ID、通过/失败/未执行数量、失败位置、未覆盖风险。无需执行的快速测试说明已有证据或不在范围内，不能把本次 E2E 通过说成所有测试通过。
