# 确认范围后执行测试

按“理解改动与环境 → 展示实际用例和执行方案 → 用户确认 → 执行并汇报”完成测试。用户只要分析时止于方案；不能因提出运行需求就跳过具体范围确认。已有会话中对同一版本、环境和范围的明确确认有效，不重复询问。

## 1. 理解当前改动，确认当前环境

读取适用的 AGENTS.md、测试说明、Git 状态和差异、E2E 用例列表与源码、执行命令及环境配置。需要 Jenkins 执行时，读取任务定义、节点和参数、上游产物及任务状态。先复用已知事实，再集中询问影响选择的缺口。

- **改动**：本次模块、功能或 Bug，直接与关联风险，当前分支、提交及未提交修改。发布验证需确定相对上次发布的累计变化，不能把上次 CI 成功当发布基线。
- **执行位置**：从哪个目录运行本地命令，或在哪个 Jenkins 实例、任务及节点执行。区分执行机和被测服务端、客户端、Agent 的部署位置。
- **被测版本**：当前环境实际运行的版本与代码来源，是否包含本次改动；本地未提交代码不会自动出现在远端产物里。无法确认版本时先说明，不能用旧安装版本证明新修改通过。
- **环境条件**：必要地址、程序路径、凭据和模型配置来源、专用测试资源及允许的清理范围。读取已有配置，只询问缺失项，不展示密码或密钥。

环境判断可做只读检查和不执行用例的范围预览。确认前不启动测试、调用模型、重装产品、改测试数据或触发流水线。存在本地与 Jenkins 两种可用方式且用户没有指定时，按项目既定流程提出一种具体方案供确认，不自行切换环境。

## 2. 选择并展示两类 E2E 范围

读取 [选例与确认](references/scope-selection.md)，依据实际可执行用例确定：

1. **本次功能 E2E**：直接验证本次新增、修改或修复行为的用例，可包含已有用例。
2. **回归 E2E**：验证受影响及关联模块原有行为的用例，按项目要求包含必要的核心冒烟。

两类用途可以重叠，最终执行按 ID 去重。给出每例的 ID、模块/功能、名称、入选原因，分别列出两类数量和去重后的实际数量。未实现的覆盖单列为缺口，不伪造编号或临时补写用例；需要编写时由 write-tests 承担。

同时展示候选版本、环境、具体本地命令或 Jenkins 任务/参数、是否构建部署、流水线是否附带其他测试与副作用，以及结果入口。让用户知道将实际执行什么，而不只看到“跑一下回归”。

完整方案展示后请求确认并等待回复，说明这是本 Skill 的执行前确认要求并链接本文件。沉默、等待超时或仅表示已阅读不构成确认。用户调整范围则修订方案；部分确认仅执行对应部分。确认前不修改正式执行清单或触发测试。

## 3. 按确认方案执行

读取 [本地与 Jenkins 执行](references/execution.md)。确认后按计划更新必要的选例清单并再次核对实际选择，然后执行；确认已经包含的构建、部署或测试动作无需再次请求许可。用户仅确认测试不能被解释为允许未知的部署、发布、提交或推送。

- 本地：在确认的目录使用项目已有命令执行，保持被测版本和范围一致。
- Jenkins：触发确认的任务及参数，记录队列和构建号，跟踪到完成或明确阻塞，收集报告；不能只启动就宣称完成。

确认后环境、候选版本、用例范围或流水线副作用发生实质变化时，先解释差异并确认变更部分。遇到运行故障不静默改跑全量、切换机器或触发其他流水线，不以反复重跑掩盖失败。任务不包含修复代码、删除测试或修改 Jenkins 全局配置。

## 4. 汇报结果

交付实际测试的版本/提交、环境、命令或 Jenkins 构建链接、计划与实际用例数量、通过/失败/未执行情况，以及报告入口和具体失败步骤。区分产品断言、测试脚本、模型调用、环境和部署问题，证据不足时注明待定位。

校验所有确认用例都有对应结果，缺失、跳过或阻塞不能算通过。核心冒烟失败导致回归未执行时分别说明；流水线成功但没有执行所选用例不等于验证通过。没有可访问报告时提供日志证据及缺口，不猜测执行结果。报告范围是否覆盖了本次改动，尚需补哪些测试或处理哪些问题，不自行发布版本。
