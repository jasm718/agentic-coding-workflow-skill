# 最小结构与职责

以下是目标项目的组织约定，不是必须一次创建完的文件清单。只落地当前选择的测试层级与运行端；没有实际用途的目录和文件只在说明中约定，等需要时再创建。

## 三层位置

| 内容 | 默认位置 | 初始化职责 |
|---|---|---|
| 单元测试 | 各组件语言惯用位置 | 复用或配置执行器，约定文件命名和发现规则 |
| 功能/集成测试 | `tests/functional/<组件或业务模块>/` | 配置测试入口及收集规则，不预置业务数据或 fixture |
| E2E | `tests/e2e/` | 配置 Midscene、Playwright、Runner 的最小运行骨架 |

单元测试不强制集中到某个目录，例如 Go 的 `*_test.go` 跟随包。pytest、前端测试工具等按项目技术栈选择；不能为了目录一致把所有测试改为同一种语言。已有等价组织方式优先复用。

## E2E 结构约定

```text
tests/e2e/
├── cases/<业务模块>/      以后编写的业务 YAML 用例，不预建模块空目录
├── setup/                所选运行端的最小资源初始化和释放
├── nodes/                需要自定义业务操作时才创建
├── support/              出现实际公共能力需求时才创建
├── scripts/              仅在 Runner 原生命令不足时添加薄入口
├── artifacts/            以后运行生成的报告与截图，本次不生成
├── midscene.config.ts    Runner 配置、发现规则和运行端绑定
├── package.json          必要依赖与手动执行命令
├── package-lock.json     与依赖声明一致的锁文件
├── tsconfig.json         TypeScript 配置
└── .env.example          仅在已有确定的配置字段时提供说明
```

**cases/**：用例按业务模块组织，web、desktop、integration 表示运行环境，不作为顶层业务分类。约定每个 YAML 文件一例，名称为 `【模块】操作和预期结果`，编号稳定；文件可以使用 `.web.yaml`、`.desktop.yaml`、`.integration.yaml` 后缀。初始化只配置发现规则和说明，不生成业务或示例 YAML。

**setup/**：只接入用户需要的运行端。web 操作浏览器；desktop 操作桌面客户端；integration 在同例中操作浏览器与客户端。真实后端或 Agent 仅作为依赖参与不自动等于 integration。资源初始化放在实际执行阶段，读取配置或枚举文件时不启动设备；按例隔离和释放，默认串行、零自动重试。未知的客户端启动方式留待实际接入，不写虚假启动逻辑。

**nodes/**：以后封装项目业务操作并注册到 Runner。当前无业务用例时不创建登录、资源创建、API 核验等节点。基础 AI 操作优先使用 Midscene 已有能力。

**support/**：以后存放有实际用途的公共代码，例如被多例使用的数据准备、条件等待或 API 请求。初始化不预制 fixture 框架、API 客户端、mock 库和数据库初始化代码。

**scripts/**：优先使用执行器现有 CLI；需要统一项目入口时只加必要编排，不能再造一个 Runner。不要预建草稿生成器、编号分配器、dev 选例工具或报告自检工程。

**artifacts/**：配置 E2E 自带的截图和可视报告输出位置，并加入忽略规则。目录在以后真正执行时生成，不在初始化运行示例以产出报告，也不另写复杂报告聚合系统。

## 依赖和配置边界

E2E 使用 Midscene、Playwright 和 Midscene Test Runner，依赖以目标项目实际需要和相容版本为准；不用其他项目的完整 package.json 或锁文件作为模板。只安装确定要用的基础工具，业务相关依赖以后增加。

浏览器采用项目约定的 viewport，无约定时可配置为 1920×1080；电脑端遵循真实桌面坐标。未选的运行端无需搭建。

`midscene.config.ts` 负责从约定路径发现用例，映射到所需运行端。每例独立执行；后续手动指定文件或用例时，不应悄悄变成全量执行。调用形式以当前安装版本支持的 API/CLI 为准。

暂时没有环境地址、业务账号或客户端路径时，不强迫用户立即确定，不写看似可用的默认值。配置应在实际运行时读取和校验，不在静态导入时要求完整环境。已确定的模型配置可写入 `.env.example` 并解释含义；`MIDSCENE_MODEL_FAMILY` 由用户显式指定，不根据模型名称自动推断。初始化不要求填入密钥，也不发起模型请求。

## 手动入口与说明

按项目已有命令体系提供各层执行入口，以及文件或单例选择方式。说明每条命令从哪个工作目录执行，参数如何传递；不能写出 package.json 中不存在的 npm 命令。无需为了统一名称替换已有可用工具。

没有业务用例是初始化的正常状态，在说明中写“尚无用例”。不要调整失败码使空收集看起来通过，也不要运行测试执行器检查这个状态。

测试说明保持简短，包含：

1. 已初始化的工具、层级和运行端。
2. 测试文件的位置与命名，如何添加第一条真实测试。
3. 手动执行目录、命令和文件/单例选择方法。
4. 后续才需填写的配置及其用途，日志与 E2E 可视报告的输出位置。
5. 初始化仅做静态检查，本次没有执行测试。

fixture、登录、业务环境、用例列表、集合划分和跨端业务数据传递，在真实测试编写时逐步落实，不作为初始化完成的前提。
